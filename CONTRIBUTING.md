# Contributing

Thanks for your interest in contributing.

## Before opening an issue

- Search existing issues to avoid duplicates.
- Include the project/repository version and relevant environment details.
- Provide clear reproduction steps and expected vs. actual behavior.
- Remove credentials, personal data, server addresses, and other secrets from logs.

## Pull requests

1. Keep changes focused and explain the problem they solve.
2. Follow the existing project structure and naming conventions.
3. Update documentation when commands, configuration, or behavior changes.
4. Run the available build and tests before submitting.
5. Include test results and note anything you could not verify.

## Security

Do not report vulnerabilities in public issues with exploit details or secrets. Contact the repository owner privately through GitHub instead.

By contributing, you confirm that you have the right to submit the code and any assets included in your changes.
